A combat agent trained in simulation

The problem

My agent reads the screen like a player (monster names, health, the skill bar) and chooses its actions. The problem: in combat, it made poor decisions.

What I built

A Python computer-vision framework, a mode that records my games so the agent can learn from me by imitation, then a simulated 2.5D arena in the style of the first Doom, calibrated on my own recordings: same camera, same image, same keys. That simulator is where it trains and gets evaluated, without launching the game.

Test bed
AION 2 (MMORPG), calibrated on my level-45 Spiritmaster

Decision chain

  1. 01

    Capture

    The screen or the game window, downscaled to 640 × 360, at 7 frames per second.

  2. 02

    Detection

    YOLO, or spotting the monsters' name plates in ≈ 3 ms per frame, without a graphics card.

  3. 03

    World state

    Targets, distances, health and mana read from the interface; objects kept in memory if they vanish for a moment.

  4. 04

    Decision

    A state machine (search, approach, combat, loot, return) or a brain trained in the simulator.

  5. 05

    Action

    Keyboard and mouse, in dry-run mode by default; F12 stops everything and releases the keys.

Step 1

Learning from my games

The demo-recording mode (REC DÉMO in the app) records what I see and what I do at the same instant: each frame is aligned with the state of the keyboard and mouse. A supervised policy learns movement from it (nine directions), stops, camera and dashes. When it is unsure, it abstains and the rules take over again.

Step 2

An arena calibrated on the real game

The world is a 2D map in meters, projected into 2.5D by a camera placed like AION 2's. I recreated my Spiritmaster's kit there, with its spirits and their rules. The agent only sees what it could read on screen: name-plate boxes, health, mana, ready skills, red on the ground and the minimap. No cheating.

Step 3 · cross-entropy method

Training

Its behavior fits in 32 readable settings: how close the boss can get before fleeing, the camera gain, the probability of using each skill, when to dash. It starts from my own habits, measured in my recordings. At each generation, variants play every scenario and the best ones produce the next generation. The new brain is only kept if it beats the old one on games it has never seen.

The unkillable boss

What it learned on its own

A scenario built so that staying in contact never pays: a 36 m square room whose corners are traps, every hit kills, and each strike is telegraphed 0.8 s ahead by a red zone.

  • flee as soon as the boss is within ≈ 13 m;
  • dash at every telegraphed strike;
  • get away from walls and corners;
  • keep attacking while backing away.

Guardrails and rigor

A

External only

It watches the screen and produces inputs, nothing else: no injection, no memory reading, no modified game files. A test checks that these techniques never appear in the code.

B

Safe by default

Dry-run mode is on at startup. Emergency stop with F12, the STOP button or the mouse in a corner; every key is released when the window loses focus.

C

Reproducible

Same seed, same game. Filming changes nothing (checked by a test). Every run can be reviewed frame by frame: decisions, keys, mouse and actual path.

D

Honest about its limits

The score measures the simulator, not the real game. A gain in damage or survival in the actual game has not been shown yet: that is the next step.
