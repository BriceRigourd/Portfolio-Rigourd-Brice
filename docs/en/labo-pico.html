A Raspberry Pi Pico 2 W that draws in Paint

The goal

Learn embedded electronics with a concrete aim: the PC sends coordinates, and the microcontroller poses as a USB mouse and draws in Paint on its own.

What I did

Six steps, from a blinking LED to a complete scene: the Pico draws a house, a tree, a sun and a star, then types each drawing's name on the keyboard. I finished with the USB identity the board announces to the PC.

Status
Completed
Board
Raspberry Pi Pico 2 W, RP2350 chip
Software
CircuitPython 10.3.1 and adafruit_hid on the board; Python, pyserial and uiautomation on the PC

A guided path prepared with Claude, followed step by step and then extended

How a stroke reaches Paint

  1. 01

    The PC

    A Python script cuts each stroke into 3-pixel steps and reads the cursor's actual position.

  2. 02

    The serial port

    One-line commands, such as “M 5 -3”, “D” or “U”. The Pico answers “OK” to each one.

  3. 03

    The Pico

    The CircuitPython program turns each command into a movement, a click or a key press.

  4. 04

    USB HID

    To Windows, it is a mouse and a keyboard like any other.

  5. 05

    The closed loop

    The PC measures the gap between the cursor and the target and has the Pico correct it, down to the pixel.

Protocol

Seven commands are enough

CommandEffect
M dx dymoves the mouse by dx, dy
D · Upresses or releases the left button: pencil down, pencil up
Ca full click, to pick a tool
T texttypes the text on the keyboard, with the AZERTY layout
K namea special key: Esc, Enter, Backspace, Tab, Delete
Pping: the Pico's answer lets the PC find the right port

Safety

A mouse that moves on its own must be able to stop

  • If the PC goes silent for more than 2 s during a click, the Pico releases everything by itself.
  • Esc stops the drawing at any time; unplugging the Pico cuts everything instantly.
  • The LED shows the state: steady means ready, off means the button is held, fast blinking means the boot file is missing.

The six steps

  1. 01First stepsCircuitPython installed by dragging a UF2 file (BOOTSEL button), the Thonny editor, then the blinking LED: pin as output, infinite loop, delay.
  2. 02The mouseThe Pico traces a square on its own, without clicking: USB HID and its relative movements, like “move 5 to the right”.
  3. 03The commandsA boot file opens a second serial port, reserved for commands from the PC.
  4. 04The drawingReady-made shapes (square, circle, star, house) or a hand-written file of points, drawn in a closed loop.
  5. 05The keyboard and the sceneThe PC locates Paint's Pencil and Text tools; the Pico selects them, draws the scene and types each drawing's name.
  6. 06The USB identityThe VID and PID numbers and the manufacturer and product names the device announces to the PC, read and then changed when the board boots.

What I learned

A

USB HID

The PC makes no difference between my mouse and the Pico. A mouse does not send a position, only relative movements.

B

Boot and configuration

The USB configuration is only read when the board is plugged in. So the program reboots the board once when it is missing, thanks to a flag kept in non-volatile memory.

C

The closed loop

Windows mouse acceleration distorts a path sent blind. Reading back the actual position and correcting in small steps of 8 pixels at most gives an accurate line, without oscillation.

D

A keyboard sends keys

Not letters: Windows translates them according to the layout. It took an AZERTY table, accents and dead key included, to type “étoile” correctly.

E

Driving a Windows interface

UI Automation, the Windows accessibility service, gives the position of every button in Paint, whatever the window size.

F

USB descriptors

VID, PID, manufacturer and product: Windows relies on them to recognize a device and choose its drivers.
