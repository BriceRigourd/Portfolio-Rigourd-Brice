Project 01 July – September 2025 Amarenco, Toulouse Python desktop app

PVsyst orchestrator

The context

Internal and external design offices uploaded new PVsyst studies to SharePoint every week. The internal technical database, updated by hand, was always a step behind: checking my 287 plants once took 2 to 3 weeks.

What I built

My first Python application with a graphical interface, built for my own use first: it scans SharePoint, keeps the latest version of every PVsyst, extracts them and shows exactly what is missing or outdated in the database. A full update now takes 1 to 10 minutes, and a simple check 10 seconds to 5 minutes.

Company
Amarenco, solar power producer
Role
Consulting engineer in PV operations (KPIs, monthly reports, OPEX budget) and author of the tools
Portfolio
287 PV plants in operation under my supervision at the end of the assignment, across 14 SPVs, totaling 67.3 MWp, mostly rooftop

July – September 2025, within the Amarenco assignment (January – December 2025)

Why this tool

Two to three weeks to check a portfolio that changed every week

The workflow before the tool

  1. 01

    Search

    Find on SharePoint the new PVsyst studies uploaded by internal and external design offices.

  2. 02

    Extract

    Open each report and note its design data.

  3. 03

    Compile

    Gather that data in an Excel file.

  4. 04

    Hand over

    Send it to the person who kept the internal technical database, so they could update it.

  1. 01

    A moving portfolio

    Some weeks, one plant got 2 or 3 new PVsyst studies; other weeks, 5 to 10 plants were redone at once.

  2. 02

    Projects that change

    Cancelled projects, renamed project codes, merged SPVs: the database quickly lost track.

  3. 03

    The cost

    With more than 280 plants, a full check took 2 to 3 weeks, and it was already out of date when finished.

The goal

Stop spending weeks copying and pasting data, and keep that time for analysis: inverter data in SynaptiQ and tracking down errors.

What the tool does

  1. 01

    Connect and locate

    Read-only connection to SharePoint, then the latest PVsyst studies of each of my SPVs are located.

  2. 02

    Sync

    Download into a local database on the workstation; when a new version arrives, it replaces the old one, which is archived.

  3. 03

    Extract

    One click on the Extraction tab: every PVsyst is read and its data gathered in an Excel file.

  4. 04

    Compare

    That file is checked against the internal technical database and the comparison file: for each SPV and project code, the tool shows which data is missing or outdated.

  5. 05

    Check the status

    Each project is cross-checked with the project register: still in service, cancelled, renamed or merged into another SPV.

  6. 06

    Leave it verifiable

    Three Excel workbooks as output, including the extraction and the comparison, to check by hand what the tool did.

  • < 10 min

    to download updates, extract everything and compare everything, instead of 2 to 3 weeks by hand

  • < 5 min

    for a simple check of the portfolio when files are already up to date, from 10 seconds

  • < 1 h 20

    for the very first download of a portfolio of more than 300 plants, i.e. 1 to 10 minutes per SPV

  • 3

    fellow engineers validated it, used it from time to time and gave me very positive feedback

What came next. Because it was built by an engineer rather than by the IT team, the tool could not be rolled out as is to the whole department. Before I left, the department decided to hand it to a development team to complete it and deploy it internally.

What I take from it. A tool I built for my own needs became a department project: I was its initiator and first developer.

The application, screen by screen

Real interface (in French), rendered with anonymized values. It was my first graphical interface: a prototype built for use rather than looks.

Under the hood

A

Desktop application

  • PySide6 + QML (Material, light and dark themes), seven settings tabs and a live run log.
  • Python backend exposed to QML through signals and slots; long jobs run in threads and stop cleanly.
  • Guaranteed read-only: any HTTP write request to SharePoint is blocked at the level of the requests library.
  • JSON configuration profiles and Windows packaging with PyInstaller.
B

SharePoint sync

  • Per-thread sessions, HTTP semaphore, requests-per-second cap, global pause on HTTP 429.
  • Versioned local database: the latest version of every PVsyst, earlier ones archived, and a manifest so nothing is downloaded twice.
  • Adjustable scope: JSON file filters and a plant list that can be imported from Excel.
C

PDF reading

  • Multiprocess extraction of PVsyst v6 to v8 reports, in French and English: tilt, azimuth, loss diagram, modules, inverters.
  • Cascading readers (pdfplumber, then pypdf, then pdftotext) and a per-file error report.
  • An "Extraction errors" tab shows which field is missing in which file.
D

Comparison and checks

  • Comparison of the extraction with the internal technical database and the comparison file, by SPV and project code.
  • Project status: in service, cancelled, renamed, merged SPVs.
  • Batch analyses on the extracted data: clipping risk (26,809 DC/AC ratios, 2,051 plants classified) and grid access contracts (2,150 read).
  • Rewritten as a typed package: mypy --strict, ruff, black, pytest, structured logs.
